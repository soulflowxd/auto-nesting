# ITKAN Nest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver STEP/DXF upload, SWYFT stock assignment, multi-sheet nesting and color-coded DXF export.

**Architecture:** A React/Vite client keeps the active job in Zustand. Browser workers import CAD and nest contours. Convex Auth, database and file storage support optional private cloud projects, following the user's scouting stack.

**Tech Stack:** React, TypeScript, Vite, Tailwind, lucide-react, Zustand, Convex, Convex Auth, RepliCAD/OpenCascade, dxf-parser, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-21-auto-nesting-design.md`

## Global Constraints

- Inches are the default everywhere; show millimeter equivalents for physical dimensions.
- No ABS grid. Fixed SWYFT combinations include 7075 3/6 mm, solid SRPP 1.75/3 mm, foam-core SRPP 6 mm, white acetal 3 mm and polycarbonate 3/6 mm.
- Group by material, color and exact stock thickness; edits invalidate affected results.
- Outside cuts are blue ACI 5 on CUT-OUTSIDE; holes are red ACI 1 on CUT-HOLES. Nominal geometry is exported without compensation.
- Accept flat prismatic STEP parts; reject unsupported geometry explicitly.
- Use a new Convex deployment when configured; local geometry workflow must work without cloud credentials.

## File map

`src/lib/reference/` contains geometry and nesting modules and regression tests. `src/lib/materials.ts`, `job.ts`, `nest-job.ts` and `validate-sheet.ts` implement stock and job rules. `src/workers/` isolates CAD and nesting computation. `src/components/` provides ImportPanel, PartList, StockPanel, SheetPreview and CloudProjects. `src/stores/job-store.ts` owns edits/results. `convex/` owns auth, schema and project functions. `public/samples/` contains runnable CAD examples.

### Task 4: Convex projects and final verification

**Files:** `convex/{schema,auth,auth.config,http,projects}.ts`, `convex/_generated/*`, `convex/projects.test.ts`, `src/components/CloudProjects.tsx`, `.env.example`, `README.md`, `THIRD_PARTY_NOTICES.md`.

**Interfaces:** Convex `list({})`, `saveCopy({json})`, `open({id})` and `remove({id})` require the authenticated owner. Project payloads are versioned JSON in Convex file storage. The save action authenticates and validates data before storing it directly; the client never supplies a storage ID. Database stores owner, name, storage ID and timestamp. All reads/deletes enforce ownership server-side.

- [x] Configure password Convex Auth and private project storage; validate JSON size, format and stock IDs on load. Use optimistic conflict handling or explicit save-as semantics rather than silent overwrites.

```ts
await expect(other.action(api.projects.open, {id})).rejects.toThrow();
```
